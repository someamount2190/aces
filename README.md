# ACES

A runnable first implementation of the Autonomous Cryptographic Evolution Sandbox.
**Experimental toy cryptography only. No security or mathematical novelty claims.**

## Run

Python 3.12+ recommended; core has no third-party dependencies.

```sh
python -m unittest discover -s tests -v
python demo.py --db demo.sqlite3
python -m aces --db demo.sqlite3
```

Open http://127.0.0.1:8765 for the administrator dashboard. The demo is explicitly deterministic integration testing, not autonomous agent operation. Use a fresh demo database on each demo run.

## Dispatch pump

The coordinator does not call a model. It publishes work; something moves that work to a role session and
returns one JSON answer. See [docs/AGENTS.md](docs/AGENTS.md) for the protocol and the role charters.

```sh
python -m aces.pump --db live.sqlite3 dispatch                     # work for roles that need it
python -m aces.pump --db live.sqlite3 deliver --work-id ID --answer '{"tool":"register","args":{...}}'
python -m aces.pump --db live.sqlite3 status
python -m aces.pump --db live.sqlite3 recover --minutes 15         # abandon stale dispatches
```

`python tools/smoke.py` drives one complete cycle through those commands with scripted answers, so the
plumbing is proven before any real session touches it: register → publish → compute → submit → breach →
finding → successor challenge.

For live models, copy `config.example.json` to `config.json`, set each model name and the provider base URL, optionally set `ACES_API_KEY`, then:

```sh
python -m aces --db live.sqlite3 --config config.json
```

Click Start. Four distinct persisted message histories use independently configurable models. No fallback fabricated responses are used. OpenAI-compatible chat-completions endpoints are supported, not all provider-specific API variants. Reasoning effort may be set per role if the selected provider supports it. Provider credentials remain in the trusted coordinator; no shell or filesystem tools are given to models.

Pause/stop prevent subsequent dispatch; a model request already in flight may finish. Close the application to shut down. Back up the database while stopped. One coordinator process per database is required. Restart resumes persisted histories and turns, within the configured lifetime turn budget. Increase the configured maximum explicitly to allow more work. A failed model call consumes one turn; errors are logged by type without secret-bearing payloads. The dashboard can be used without a provider.

## Implemented

- Four role-scoped tool dispatchers and distinct persistent LLM sessions.
- Bounded executable byte-permutation VM: xor, add, key-dependent xor/add, byte rotation. No arbitrary Python, imports, filesystem or network operations.
- Exhaustive byte/key correctness checks before candidate registration, specifications and reproducible vectors.
- Random target plaintext and random toy key generated by the trusted engine.
- Open-design and black-box publication; built-in solver tool requires a program and known pair. No encryption/decryption oracle yet.
- Persistent immutable-by-interface challenge payloads; a transaction permits replacement only after verification of the latest version, with its exact parent id.
- Exact target plaintext comparison independent of the model; atomic breach event, reward and escalation authorization. Duplicate and concurrent submissions cannot duplicate candy.
- Observer findings associated with confirmed breaches, separate generator feedback, full event trail.
- Durable coordinator work items; a completed turn's session history, cursor and turn charge commit atomically and duplicate completion is idempotent.
- Loopback administrator dashboard, lifecycle controls, audit export, CSRF token and Host validation on reads.

## Isolation and scientific limits

Models receive JSON views and invoke a finite operation language, not executable Python or host sessions. These interfaces enforce capability separation inside a trusted coordinator. The database and dashboard are administrator-only: never mount them in an agent environment or expose the dashboard publicly. This is **not** OS isolation between four hostile native processes. No guarantee of absolute semantic blindness or covert-channel freedom is made; candidate text is untrusted model content and can carry indirect signals. Separate model histories cannot erase shared pretrained knowledge.

Bubblewrap is present in the build environment but cannot create namespaces; Docker is absent. Arbitrary generated source execution is therefore deliberately unavailable. The VM cannot express arbitrary novel primitives. Real LLM operation has not been demonstrated in the build environment because no task-authorized configured endpoint was available. The shipped tests mock provider decisions and do not count as real-model acceptance.

Observer feedback is an evidence-linked hypothesis, not independently verified cryptanalysis. A known-pair exhaustive search on an 8-bit key is deliberately trivial. Rotating a weak cipher does not demonstrate increased security; parameter or construction replacement is allowed after breach, but automatic difficulty ordering is not established. Black-box failure is not evidence of security. Candy is accounting, not model training or weight updates.

## Remaining work

- Real-provider acceptance test and multi-hour recovery exercise.
- Container or microVM workers for arbitrary candidate/attack programs, host isolation penetration tests, stronger metadata declassification.
- Stale work-item recovery and reconciliation when a process stops during a provider call or after a tool side effect; retry backoff, per-tool deadlines and memory limits, token/cost accounting and a resource configuration UI.
- More expressive mathematical language and proof obligations; general source artifact registry.
- Key recovery, forgery, protocol and statistically evaluated distinguishing verifiers.
- Query-budgeted oracles, research ingestion with source/date/confidence records.
- Full normalized schema and migrations matching all entities in the master prompt; complete construction lineage and agent health metrics.
- Administrative suspension of an active challenge (current controls suspend dispatch only), safe reset UI, detailed session inspection, stronger HTTP hardening.

The delivered scope is a functioning constrained foundation and integration cycle, **not completion of all master-prompt acceptance criteria**. Work-item bookkeeping protects coordinator session state; it does not provide exactly-once provider execution or exactly-once tool side effects across crashes.
