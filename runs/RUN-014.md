## The three fixes held

1. **Schema:** `analyse differential` was called correctly first time — `difference` + `pairs`. In run 013 the
   same call was a list of pairs and cost a turn.
2. **Budget:** the challenge advertised 64 and the engine counted 8. Run 012's contradiction (public 0, tool
   64) is gone.
3. **Executable refutations:** `resolve` was accepted only because a run existed after the hypothesis, and
   the work item that tested it is recorded on the hypothesis (`work_item`). Run 013's docstring refutation
   is now impossible.

## Where the review layer is weak

The Reviewer called this **sound**, and its advice reads as if the sequence were "cheapest probe before
compute". It was not: `compute` at step 5 came *before* the differential analysis at step 6, and step 7 was
a second enumeration after the differential had already come back flat. Two enumeration calls against a
2^128 space, on a challenge whose own text says chosen-plaintext probing is the route, is the
`enumeration_as_analysis` pattern.

So the verdict is defensible — the Adversary did inspect, predict, probe and refute on evidence — but the
**review was not accurate about the order it was reviewing**. A reviewer that paraphrases the record
imprecisely will pass process flaws it was built to catch.

That is the next defect to fix: give the Reviewer the ordered action log as data (tool, arguments, result
summary, timestamp) rather than a prose summary, so "was the cheap probe before the expensive one" is a fact
it can check rather than a narrative it has to reconstruct.
